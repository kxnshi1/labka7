# GitHub: выполнить после локальной проверки

Архив не содержит историю Git и не создаёт PR. Сначала нужна исходная ЛР7 в main. Не удаляйте .git из своего клона.

1. Откройте клон репозитория: `git status`, `git remote -v`. Убедитесь, что main содержит обе папки проекта ЛР7.
2. Создайте ветку: `git switch -c feature/api-tests`.
3. Скопируйте содержимое папки AgroMarket_Lab8 в корень клона с заменой файлов, включая .github и .gitignore. Не переносите .env и node_modules.
4. Настройте локальный .env.test, выполните `npm ci`, `npm test`, `npm run coverage` в серверной папке, `npm ci`, `npm run build` в React.
5. В корне: `git status`. Проверьте, что секретов нет. Затем `git add .`, `git diff --cached --stat` и `git commit -m "test: add API tests and CI for lab8"`.
6. `git push -u origin feature/api-tests`.
7. На GitHub откройте PR feature/api-tests → main; заполните шаблон, назначьте напарника.
8. Дождитесь зелёных test и frontend. Для реального PostgreSQL это первый подтверждённый прогон данной сборки.
9. Настройте защиту main: PR, 1 approval, обе проверки, запрет force pushes; обход правил не разрешать.
10. Напарнику оставьте минимум 2 комментария к строкам, один через suggestion. Исправьте замечания к своему PR и отправьте новые коммиты.
11. Для красного PR временно замените 200 на 201 в health.test.js, сделайте отдельный commit и push, проверьте блокировку merge. Верните 200, commit и push. Сохраните собственные скриншоты GitHub.
12. После зелёного CI и review выполните Squash and merge. Локально: `git switch main`, `git pull`. Удаление ветки выполняйте после проверки, что результат слияния получен.

Не публикуйте вымышленные review-комментарии или чужие скриншоты как свои. Указанные действия в подготовленном архиве отмечены как предстоящие.
